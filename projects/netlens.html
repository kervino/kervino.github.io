PROJECT 02 / CASE STUDY

From packets
to patterns.

The problem

Packet captures can contain large volumes of traffic. Manually inspecting each packet in Wireshark is useful for detailed investigations, but repetitive questions — which IPs are most active, what protocols appear, and whether unusual connection attempts occur — benefit from automation.

What I built

NetLens is a command-line tool for analyzing saved PCAP files. It uses Scapy to decode packet layers and Python to summarize network activity, producing both terminal output and downloadable-style report files saved locally.

  • Loads offline PCAPs and reports source/destination IPv4 activity.
  • Counts TCP, UDP and other packets, and extracts transport-layer port numbers.
  • Exports human-readable .txt and machine-readable .json reports.
  • Flags possible TCP SYN port scans when one source targets at least five unique ports on the same destination during a fixed 60-second window.
  • Handles invalid capture files gracefully and includes automated CLI integration tests.

How detection works

NetLens looks for initial TCP SYN packets without the ACK flag, groups traffic by source IP, destination IP and fixed time window, then counts the unique destination ports using sets. When the count reaches five, it records a potential scan finding. Repeat attempts to the same port aren't counted twice.

I checked the behavior with synthetic captures: a concentrated seven-port scan sample produced a finding, while an ordinary office-traffic sample produced no finding under the current rule.

Engineering and validation

I built the analysis in small increments, then refactored protocol counting into a reusable function. Python's unittest framework runs four integration tests covering valid and invalid PCAP handling, positive scan detection, and the absence of scan findings in the ordinary traffic fixture.

Try it locally

The repository includes setup instructions and safe synthetic test captures. The command-line interface takes a PCAP filepath:

.venv\Scripts\python.exe src\analyze.py tests\fixtures\netlens-concept24-portscan.pcap

What I'd improve next

The detector is a heuristic, not an intrusion detection system. Future iterations could use sliding windows, richer features, performance tests on larger traces, and clearer confidence/context for findings. An interactive dashboard could consume the JSON output.

Scope and limitations: This project analyzes offline PCAP files; it does not perform live monitoring or claim to confirm attacks. Detection can produce false positives and miss scans, particularly around fixed-window boundaries. The illustrated IP addresses and traffic come from synthetic practice captures.
